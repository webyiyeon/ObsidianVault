## 변경관리 

- 절차
	1. ==변경의뢰서== 작성 (생산팀 및 현장 부서: 기안 부서)
		- 기안 부서 내부 결재 
		- 설비 변경 요소 평가, 공정 위험 지수 평가
			⇒ 이 때, 평가 점수로 What-if 인지 확인 
		- 모든 항목이 Check List 대상
		- 한 변경에 여러 Check List 존재 가능 (예: 탱크 신설 시에 최소 4~5개)
		- RIK 판정: 완전히 동일한 스펙의 경우 정비/점검으로 판단하여 변경관리 X 
		- 변경 분류 1
			- 정상: 보고 완료 후 변경
			- 비상: 선 변경 후 보고 
		- 변경 분류 2
			- 임시: 도면이 바뀌지 않는 임시 변경, 30일 후 원상복구
			  (예: 공정 테스트, 위험물 추출 등)
			- 영구: 임시 변경 외의 변경. 도면에 적용되는 변경.
	2. 위험성 평가 (기술공정팀: 주관 부서)
		- 이 때, 설비 변경 요소 평가와 공정 위험 지수 평가 내용 검토
			- 합의 하에 주관 부서에서 수정
			- 정/부 담당자 지정 후 해당 담당자만 수정 가능하도록 설정 
		- 위험성 평가 결과 위원회 소집 필요 판정 시, ==변경관리 위원회== 결성 
			- 평가 점수가 위원회 소집 필요 점수일 때는 자동, 아닌 경우에는 주관 부서에서 결정하도록 설정
			- 위원장: 기술본부장(fixed)
			- 위원회: 별도 승인 과정은 X. 추후 합의 완료 여부만 관리 변경
			  (기안 부서, 작업 부서, 공무 부서, 계전 부서 등)
	3. 변경검토서 작성 (기술공정팀)
		- 각 담당 부서별 보완 필요 사항 및 검토 사항에 대한 내용 전달 
	4. 첨부파일: 공정안전자료, 사후증빙자료, 교육결과 실시보고서, 임시 변경일 경우 원상 복구(YN)
		- 기간(30일) 지났는데 아직 복구 안 한 경우, 새로 변경관리 작성 필요 
		- 도면: 최종 완료 후 제출 *→ 추후 결정*
	5. 가동 전 안전 점검 (생산팀 및 현장 부서)
		- ==가동 전 안전 점검 보고서==(PSM) *→ 안전팀 논의 필요*
- 변경관리 간 의존성 X
- 변경관리 : 가동 전 안전 점검 = 1 : 1
	- 변경관리를 하면 무조건 가동 전 안전 점검 진행 필요
- 리드 타임: 일주일(7d) ~ n주, 정수(TA) 때는 1년까지도 감 (list 작성하듯 미리 변경)
- 나의 할 일 *→ 추후 결정*
- Dash Board *→ 추후 결정*
- 모바일 X / 협력사 X
- 발의서 번호, 변경관리 번호 
- 날짜 조정 가능 
- 주로 설비(Machine) 변경 대상, 간혹 절차(Method) 변경
- *HAZOP은 공정위험성평가를 별도로 진행하기 떄문에 추후 안전팀과 논의*
