## 변경관리

- 절차
	1. 변경의뢰서 작성 (생산팀 및 현장 부서: 기안 부서)
		- 기안부서 내부 승인: 담당 → 팀장 → 부서장 (fixed)
			- 반려/회수 기능 필요
				- 반려: 승인자에게 노출
				- 회수: 기안자에게 노출
				- 동작은 동일. 의뢰서 작성 단계로 돌아가 기안자가 수정하여 다시 기안 올릴 수 있도록 처리.
			- 팀장 결재 중에는 일부 내용 수정 가능
			- 부서장 승인 이후에는 수정 불가
		- 의뢰번호(예: 생산-26-21)/변경번호(예: O-26-141)는 중간에 빈 숫자를 끼워 넣을 수 있도록 선택 가능
		- `희망완료일` ⇒ `작업완료일`: 가동 전 안전점검 직전 단계까지 걸렸으면 하는 작업 희망일
			- 작업완료일을 지나는 경우 `연장 사유` 작성 필요
				- 연장 사유 미 작성 시, 6개월 초과 시 자동 변경 취소 
				- 작업완료일이 해당하는 월초(1일)에 `임박` 
				- 작업완료일이 지난 경우
		- 변경 구분
			- 정상: 보고 완료 후 변경
			- 비상: 선 변경 후 보고
		- 변경 분류
			- 임시: 도면이 바뀌지 않는 임시 변경. 30일 후 원상 복구
				- 가동 전 안전 점검 2회 진행
					- 변경 후 1회, 원상 복구 후 1회
				- 임시 변경 이후 원상 복구 하지 않기로 결정된 경우, (30일 초과 시,)
				  해당 임시 변경은 복제하여 신규 영구 변경으로 의뢰
			- 영구: 임시 변경 외의 변경. 도면에 적용되는 변경.
		- 작업 시기
			- Shutdown 시
			- TA(정수) 시
		- 가동 전 안전 점검 등급 필요 X
		- 공정 X ⇒ 단위공장 O (예: Utility, HOT, COLD)
		- 변경 등급 O (예: 중요구조, 공정위험, 일반변경)
		- 각 설비별 변경 관련
			- 변경 전후 내용은 필수값 X ⇒ `비고`로 문구 변경?
			- 설비코드 ⇒ 아이템 No. 
		- ==공정위험지수==, ==중요변경요소== 작성 
		
	2. 변경의뢰서 접수 (기술공정팀: 주관 부서)
